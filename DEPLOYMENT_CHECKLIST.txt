DEPLOYMENT STEPS (Staging First)
═══════════════════════════════════════════════════════════════════════════════════

STEP 1: Prepare Environment
  ☐ Clone repository to staging server
  ☐ Create .env file with staging credentials (see below)
  ☐ Create Python virtual environment
  ☐ Install backend dependencies:
    .venv/Scripts/pip install -r requirements.txt

  ☐ Navigate to frontend directory
  ☐ Install frontend dependencies:
    npm install

STEP 2: Initialize Database (PRODUCTION ONLY)
  ⚠️  STAGING: Use test database (auto-initialized)
  ⚠️  PRODUCTION: Run migrations carefully
  
  # Check current schema version
  psql $DATABASE_URL -c "SELECT version FROM schema_version;"
  
  # Apply pending migrations
  cd backend/migrations
  for migration in *.sql; do
    psql $DATABASE_URL -f "$migration"
  done

STEP 3: Build Frontend
  ☐ npm run build (creates dist/ directory)
  ☐ Verify build output: du -sh frontend/dist/
    └─ Should be ~500KB-2MB gzipped

STEP 4: Start Backend
  ☐ Set environment variables (see .env template below)
  ☐ Start Uvicorn:
    .venv/Scripts/python.exe -m uvicorn backend.main:app \
      --host 0.0.0.0 --port 8000 --workers 4
  
  ☐ Verify startup:
    curl http://localhost:8000/health
    # Expect: {"status":"ok","service":"IntelliResume AI","version":"2.0.0"}

STEP 5: Verify Backend
  ☐ Test analysis endpoint:
    curl -X POST http://localhost:8000/api/analyze/comprehensive \
      -H "Authorization: Bearer demo-token-123" \
      -F "resume=@test_resume.txt" \
      -F "job_description=@test_jd.txt"
    # Expect: 202 with session_id

STEP 6: Serve Frontend
  ☐ Copy dist/ to web server (nginx, Apache, S3, CDN)
  ☐ Configure web server to:
    └─ Serve static files with cache-busting headers
    └─ Route all non-static paths to index.html (SPA routing)
    └─ Proxy /api/* to backend (http://localhost:8000)

STEP 7: Run Smoke Tests
  ☐ Open https://staging.yourdomain.com in browser
  ☐ Upload test resume and JD
  ☐ Verify results display correctly
  ☐ Test upgrade flow (don't complete payment)
  ☐ Check browser console for errors (F12)

═══════════════════════════════════════════════════════════════════════════════════
ROLLBACK PROCEDURE (If Deployment Fails)
═══════════════════════════════════════════════════════════════════════════════════

IF BACKEND DEPLOYMENT FAILS:

  1. Stop all backend processes
  2. Restore previous backend code from git
  3. Restart backend with previous code
  4. Verify health endpoint responding
  5. Clear any cached data that might be incompatible
  6. Monitor for errors

IF DATABASE MIGRATION FAILS:

  1. Stop all backend processes
  2. Restore database from pre-migration backup
  3. Verify data integrity
  4. Restart backend
  5. Investigate migration issue
  6. Do NOT try migration again without fix

IF FRONTEND DEPLOYMENT FAILS:

  1. Restore previous frontend code to web server
  2. Clear browser cache/CDN cache
  3. Verify page loads correctly
  4. If needed, temporarily serve from staging
